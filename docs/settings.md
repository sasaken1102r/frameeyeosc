# Settings and status file

[Back to the README](../README.md)

## Settings

Settings are in `~/.config/frameeyeosc/config.json`. The panel writes it, and you can also edit it by hand. frameeyeosc checks it 10 times a second and applies changes without a restart. Missing keys use the defaults and unknown keys are ignored. If the file is broken or a value is out of range, frameeyeosc keeps the previous settings and reports the error (in the panel and in the status file).

```json
{ "output": "vrchat", "gaze_min_cutoff": 0.3, "lid_sync": 0.6 }
```

| Key | Option | Default | What it does |
|---|---|---|---|
| `sending` | | `true` | `false` pauses sending (in VRChat mode `EyeTrackingActive=false` is sent once, as `eye_tracking_active` says; in LiveLink mode relaxed open eyes looking ahead) |
| `output` | `--output` | `"vrchat"` | `"vrchat"` sends avatar parameters to VRChat, `"livelink"` sends Live Link Face packets to VRCFaceTracking's LiveLink module, `"frameeyeosc"` sends to VRCFaceTracking's FrameEyeOSC module. `"etvr"`, the ETVR mode removed in 0.10, is read as `"vrchat"` (see [Going back to an earlier release](update.md#going-back-to-an-earlier-release)) |
| `host` | `--target` | `"auto"` | `"auto"` = the PC Steam Link is streaming from, else an IP address or host name without a port |
| `port` | `--port`, `--target` | `null` | `null` = 9000 for `vrchat`, 11111 for `livelink`, 11112 for `frameeyeosc` |
| `prefix` | `--prefix` | `"/FT"` | Parameter name prefix; `""` for none. In LiveLink mode only used for the pupils sent straight to VRChat (`pupils_to_vrchat`) |
| `lan_only` | `--no-lan-only` | `true` | Send only inside your home network: every destination (the main one, the pupils sent straight to VRChat, and each of the [other apps](outputs.md#other-apps)) has to be a loopback (127.x, ::1), private (10.x, 172.16-31.x, 192.168.x, IPv6 fc00::/7) or link-local (169.254.x, fe80::) address, or 100.64-127.x, which VPNs such as Tailscale use (shown as VPN). Any other address, a public one, is refused: nothing goes there, the log says so and the panel shows it. `false` allows public addresses, marked as public. Multicast and broadcast addresses are never sent to. For now the Steam Link PC (`"auto"`) is never refused, only logged, until the addresses Steam Link uses have been checked |
| `extra_outputs` | `--extra`, `--no-extras` | `[]` | Up to 3 more destinations for the eye data; see [Other apps](outputs.md#other-apps) |
| `eye_tracking_active` | `--eye-tracking-active` | `"bool"` | How `EyeTrackingActive` is sent in VRChat mode: `"bool"` (true / false), `"float"` (1.0 / 0.0; some avatars need it) or `"off"` (never, not even the one-time "not active" on pausing or losing tracking). The other modes never send it |
| `steamlink_params` | `--steamlink-params` | `false` | In VRChat mode, also send the avatar parameters SteamVR's Steam Link sends from its own OSC (`LeftEyeX`, `RightEyeLid`, ...), for avatars made for those; see [Avatars made for Steam Link's OSC](outputs.md#avatars-made-for-steam-links-osc). Never prefixed. The other modes ignore it |
| `native_eyes` | `--native-eyes` | `false` | In VRChat mode, also send VRChat's own eye tracking input (`/tracking/eye/*`), which moves the eyes of avatars without VRCFT parameters (see [Native VRChat eye tracking](outputs.md#native-vrchat-eye-tracking)); a switch on the Output tab |
| `vrc_face_tracking` | `--vrc-face-tracking` | `false` | In VRChat mode, also send VRChat's Face Tracking input (`/tracking/face/v1`): each eye's eyelid, widening and gaze, with the eye cameras the squint and pupils, and the brows raised with `brow_from_widen`, for avatars set up for VRChat Face Tracking (see [VRChat Face Tracking](outputs.md#vrchat-face-tracking)); a switch on the Output tab ("Send to Face Tracking too") |
| `camera_lids` | `--no-camera-lids` | `true` | Use the eye cameras' values (see [Eye cameras](eyecam.md#eye-cameras)) once they are set up: the eyelid from relaxed open up (widening) and where the camera sees an eye closed or, through a squint, open, squints and pupil size. `false` = Valve's values only, and frameeyeosc also has eyecam-rec stop working out eye values from the video (`live off`; eyecam itself keeps running, see [Turning it off and removing it](eyecam.md#turning-it-off-and-removing-it)). "Use / Don't use" in the Basic tab's "Eye cameras" row |
| `pupils_to_vrchat` | `--no-pupils-to-vrchat` | `true` | In LiveLink mode, send the eye cameras' pupil size straight to VRChat (port 9000 on the same PC), since the LiveLink module carries no pupils. Other modes ignore it |
| `pupil_bits` | `--pupil-bits` | `0` | Wherever the eye cameras' pupils go to VRChat, also send the dilation as this many bool parameters (`v2/PupilDilation1`, `2`, `4`, `8`), for avatars that take it bit-packed; `0` = the float only. 1 to 4. See [Pupils on avatars with bit parameters](eyecam.md#pupils-on-avatars-with-bit-parameters). "How the avatar takes pupils" on the Output tab |
| `raw` | `--raw` | `false` | No smoothing, and none of the time-based steps (glitch removal, gaze holding, the quality check, blink hold, holding the sideways gaze far down) |
| `gaze_min_cutoff` | `--gaze-min-cutoff` | `0.3` | Lower = steadier gaze at rest, more lag |
| `gaze_beta` | `--gaze-beta` | `1.5` | Higher = follows fast eye movements with less lag, and settles sooner after one |
| `gaze_d_cutoff` | `--gaze-d-cutoff` | `0.5` | Lower = tracker noise loosens the gaze filter less, and the gaze glides softly into a quick eye movement instead of snapping to it |
| `gaze_deadzone` | `--gaze-deadzone` | `0.005` | Gaze changes smaller than this are ignored (1.0 = 45°); the gaze can stop up to this far short of where the eyes landed |
| `gaze_hold_below` | `--gaze-hold-below` | `0.5` | Hold the gaze while either eye's openness is below this; `0` turns it off. One eye alone below it holds the gaze for up to 1 s (a wink); longer, and that eye's reading is taken as wrong and the other eye moves the gaze |
| `independent_eyes` | `--independent-eyes` | `false` | Instead of the shared gaze for both eyes, turn the eyes in by a fixed 2° between them (as if looking about 2 m away), around the shared sideways gaze; each eye keeps its own up/down, and an eye whose gaze is unreliable takes the other's. The Frame's own per-eye sideways gaze isn't used: with the eyes on a dot 0.9 m away (4.4° between them) it read 0.1-17.3° apart, and while recording it swung between under 1° and over 4° 20-32 times a minute (the avatar went cross-eyed, 13-19° at the p95). Intentional cross-eye still shows: Valve's left - right is let through once it has stayed at 20° or more for 0.5 s (or 25° or more for 0.25 s) with both eyes at least 0.7 open and looking no more than 15° down, having got there within 2.5 s of being below 15° and not right after a blink (0.3 s), until it stays below 15° for 0.15 s. In a wear where Valve reads the eyes turned in all along, the three lines go up together to 10° above the median of its last 60 s. While the "Track Dominant Eye Only" setting is on, both eyes get the tracked eye's gaze either way |
| `own_eye_gaze` | `--own-eye-gaze` | `0` | With `independent_eyes`, how much of each eye's own sideways gaze from Valve is used, `0`..`1`: `0` the turned-in gaze above, `1` each eye's own as Valve reads it (wobbly, since it swings as above), in between that far from one to the other. Eyelids, smoothing and holding stay as they are, and an eye whose gaze is unreliable still takes the other's. "Own gaze per eye" on the Gaze tab's "Reach" page |
| `gaze_quality_limit` | `--gaze-quality-limit` | `0` (off) | Optional safety net: ignore an eye's gaze while the Frame's own uncertainty (covariance) for it is above this (for example `0.03`). The other eye moves both, and if both are above it the gaze is held. Eyelids aren't affected. On a well-fitted headset it made no measurable difference, because the uncertainty only rises while the eyes are mostly shut, where `gaze_hold_below` already holds the gaze |
| `despike` | `--no-despike` | `true` | Remove one-sample glitches in gaze and openness (median of 3 samples; everything arrives ~11 ms later) |
| `lid_min_cutoff` / `lid_beta` | `--lid-min-cutoff` / `--lid-beta` | `6.0` / `5.0` | Eyelid smoothing, the same way as for gaze |
| `lid_closed` / `lid_open` / `lid_widen_start` / `lid_wide` | `--lid-closed` ... | `0.30` / `0.80` / `0.92` / `1.00` | How Frame eye openness maps onto closed / relaxed / widened |
| `lid_widen` | `--lid-widen` | `"normal"` | How easily an eye with an eye fit widens: `"off"`, `"low"`, `"normal"` or `"high"` (see [Eye fit](eye-fit.md#eye-fit)). Eyes without a fit use `lid_widen_start` / `lid_wide` instead |
| `widen` | `--no-widen` | `true` | Whether the eyes widen at all. `false` = never: no eyelid goes out above relaxed open (VRChat's `EyeLid` 0.75, `EyeWide` 0 through VRCFT's LiveLink and FrameEyeOSC modules), whatever the eye cameras, `lid_widen` or the lid marks say; closing, blinks and the eye cameras' squint stay exactly as they are. "Widening" (On / Off) on the Eyelids tab |
| `brow_from_widen` | `--brow-from-widen` | `false` | Raise the avatar's brows when the eyes widen. The eye cameras don't see brows: an eye widened past 15 % raises its brow, up to `brow_strength` at full widening, also with `widen` off. A closing or closed eye keeps its brow; in a wink the closed eye's brow follows the open one's. Brows are never lowered. VRChat directly: `v2/BrowExpressionLeft` / `Right` / `BrowExpression`, `v2/BrowUpLeft` / `Right` / `BrowUp`, `v2/BrowInnerUp`, `v2/BrowOuterUp` (all 0 once when it stops); LiveLink: `BrowInnerUp` and `BrowOuterUpLeft` / `Right`; FrameEyeOSC: the packet's brows block (108 bytes). Works on avatars with brow parameters. "Widen raises brows" on the Eyelids tab |
| `brow_strength` | `--brow-strength` | `0.8` | How far `brow_from_widen` raises the brows at full widening, `0`..`1`. "Brow raise strength" on the Eyelids tab |
| `lid_scale_left` / `lid_scale_right` | `--lid-scale-left` / `--lid-scale-right` | `null` (learned) | Fixed per-eye multiplier instead of the learned one. For an eye with an eye fit, a fine-tune after the fit instead: 0.9 makes that eye read 10% less open (it closes sooner and widens less), `null` = 1.0. The full eye fit and its "Reset" set it back to `null` |
| `lid_calibration` | `--no-lid-calibration` | `true` | Learn eyelid calibration |
| `lid_sync` | `--lid-sync` | `0.4` | Evens out small left/right eyelid differences; larger ones (winks) pass through. `0` turns it off |
| `blink_hold_ms` | `--blink-hold-ms` | `80` | Once an eye is closed, it is sent fully closed for at least this long, so short blinks reach other players. `0` turns it off |
| `blink_sync_below` | `--blink-sync-below` | `0.35` | When one eye is closed and the other is below this (VRCFT scale), both are sent closed. Winks, with the other eye open, pass through. `0` turns it off |
| `camera_lid_floor` | `--camera-lid-floor` | `0` | While the [eye camera](eyecam.md#eye-cameras) sees an eye open, its eyelid is sent no lower than this (VRCFT scale, 0 to 0.75), so a hard squint shows narrowed and the squint parameter carries the rest. Blinks and an eye the camera sees closed still close. Eyes without the camera's values are unchanged. `0` turns it off. "Lowest eyelid when narrowed" on the Eyelids tab |
| `camera_close_gate` | `--no-camera-close-gate` | `true` | How an [eye camera's](eyecam.md#eye-cameras) "closed" in one eye only is used: as a blink when the other eye's camera sees its eye closed too (within 0.15 s) or Valve's openness reads the other eye below 0.5, as a wink once it has lasted 0.2 s; until then the eye stays as the camera last saw it open, so a short "closed" the camera reads for an open eye (for example where it doesn't find the pupil) doesn't close it. While Valve's gaze is more than 18° down, no camera "closed" is used unless Valve reads an eye below 0.25, a real blink (looking down, the upper lid covers the pupil and both cameras read the eyes closed, and Valve's own eyelid of an open eye moves around 0.5). "Looking down" and "a blink there" each last 0.15 s past their last sample. `false` = every camera "closed" at once, as before |
| `camera_closed_doubt` | `--no-camera-closed-doubt` | `true` | With the [eye cameras](eyecam.md#eye-cameras): an eye's camera "closed" that has lasted longer than a blink while Valve reads that eye open and is sure of it is taken as open (lying down, the camera can lose the pupil at the edge of its picture). `false` = it is not, for a headset where Valve reads a closed eye as open: on one Frame with SteamOS 0.4.3, Valve read a winking right eye at 1.00 and sure of it, so its winks opened again after 0.5 s. Looking far to the side is checked either way |
| `lid_open_snap` | `--lid-open-snap` | `0.53` | For eyes without the [eye camera's](eyecam.md#eye-cameras) eyelid: an eyelid to be sent at least this open (VRCFT scale, 0 to 0.75; a fitted eye's scale `lid_scale_*` applies after it, so a fine-tune still shows, while for an eye without a fit it comes after the scale, which maps that eye) eases smoothly up to a normally open eye (0.75), reached halfway from this value, so an eye read nearly open goes out open. A value above 0.75 from a build where this was a share of the open reading is converted once (0.80 -> 0.53). "Treat nearly open as open" on the Eyelids tab's "Blinks & squint" page |
| `camera_lid_open_snap` | `--camera-lid-open-snap` | `0.63` | The same for eyes with the [eye camera's](eyecam.md#eye-cameras) eyelid: an eyelid at least this open (VRCFT scale, 0 to 0.75) eases smoothly up to a normally open eye, so a small dip of an open eye goes out open. | `gaze_offset_x` / `gaze_offset_y` | `--gaze-offset-x` / `--gaze-offset-y` | `0` / `0` | The gaze that counts as straight ahead, from -0.5 to 0.5 (1.0 = 45°; + is right / up). Set by the eye fit |

Command-line options win over the file. They go in `~/.config/frameeyeosc/env` (then `systemctl --user restart frameeyeosc`):

```sh
FRAMEEYEOSC_ARGS="--gaze-min-cutoff 0.3 --lid-sync 0.6"
```

Whatever is set there can't be changed from the file, and the panel shows it as "Locked by command line". Run `~/.local/bin/frameeyeosc --help` for all options, including `--config` for another settings file.

## Status file

frameeyeosc writes what it is doing to `$XDG_RUNTIME_DIR/frameeyeosc/status.json` (usually `/run/user/1000/frameeyeosc/status.json`) ten times a second: whether it is sending, the destination, messages per second, the eye tracker's samples per second (`tracker_rate`), how well frameeyeosc keeps up with them (`missed_rate`: samples the eye tracker published in the last second that frameeyeosc didn't read; `max_processing_ms`: the longest it took over one sample in the last second; `dropped_rate`: datagrams dropped in the last second because the network was too busy), the latest raw and sent values, the calibration, the settings in effect, which of them are locked by the command line, any config error, why the eye data can't be read if it can't (`source_error`), which eye the Frame tracks alone while the "Track Dominant Eye Only" setting is on (`dominant_eye`: `"left"` or `"right"`; `null` while it is off), whether a relaxed open eye reads 1.0 so widening can't come through (`openness_saturated`), the eye cameras (`camera`: whether their values arrive, `used` / `pupil_used` for each eye, or why they can't be read; `null` while eyecam isn't running), where pupils go in LiveLink mode (`pupil_target`), `lan_only`, what kind of address the main output and the pupils go to (`net` / `pupil_net`: `"lan"`, `"vpn"` or `"public"`) and why one is refused (`refused` / `pupil_refused`, e.g. `"public address"`), each of the [other apps](outputs.md#other-apps) (`extras`: its entry, where it goes, `net`, its rate, and why it sends nothing, `refused` / `last_error`), the last problem frameeyeosc logged with its time (`last_error`: `text` and `time`, kept after it clears, e.g. "No Steam Link connection found; waiting for one"; `null` before the first), and the latest eye fit measurement. The panel reads it. The folder and the file are readable only by you, live in memory, and are gone after a reboot. Only the latest values are kept. The status file is frameeyeosc's own and can change between releases; it is not an interface for other programs (the packets in [docs/protocol.md](protocol.md) are).
